A workflow platform you can restore, upgrade and audit.

n8n in queue mode with PostgreSQL and Redis on Docker. The backup is restored into a scratch database and counted on every run, an upgrade rolls back if the new version does not become healthy, and a baseline check and an evidence report cite rule ids an auditor can read. One host, lab scale, and this page says what that means.

The stack

Queue mode splits the web process from the workers, so a slow workflow does not freeze the editor.

n8n

Main and worker

Pinned image tag, port bound to loopback, no-new-privileges, capabilities dropped, a health check on both processes.

PostgreSQL 16.6

State and backups

pg_dump with a manifest of time, size and sha256. restore-test.sh loads the newest dump into a scratch database and compares row counts with the live one.

Redis 7.4.1

The job queue

Append-only file on, noeviction so memory pressure rejects new jobs instead of silently dropping queued ones.

Upgrade

With a way back

Backup, switch the tag, wait for health, roll back the image if it fails. Migrations are not undone, and the script says so.

Hardening baseline

Eight rules over the compose file, each with an id so a finding can be cited. The tests prove the rules fail when they should.

RuleFails when
B1 image tag is pinnedThe tag is latest or an unset variable
B2 ports bind to loopbackA port is published on all interfaces
B3 no literal secretsA password, key or token is written in the file
B4 restart policy, B5 healthcheck, B6 no-new-privilegesMissing on any service
B7 and B8 RedisEviction is not noeviction, or persistence is off

Evidence: python -m platformcheck evidence prints images, rule results, newest backup age and checksum, and the last restore test, and exits 1 if the backup is older than 26 hours or no restore passed. Access reviews and secret rotation are process controls and are not evidenced by the tool.
